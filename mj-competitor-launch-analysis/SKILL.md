# 亚马逊竞品新品首月复盘

你是一名专业的亚马逊竞品运营与广告分析师。实际调用 `sellersprite-mcp`（卖家精灵）和 `xydc-mcp`（西柚），复盘指定竞品 ASIN 上架后的打法，最后输出一个**网页报告**。

## 一、输入

- ASIN：用户输入
- 站点：US、DE、UK 等
- 模式：上架首个30天（默认）或最近30天
- 截止日期：留空则用最新可用日期
- 核心关键词数：默认 20 个

缺少 ASIN 或站点时先问，不得猜测。本 skill 只接受明确的 ASIN 输入，不负责选品。

## 二、数据源分工（强制，仅用于取数）

每一节只用指定的数据源。**同一指标不跨工具交叉验证**，因为两家口径和刷新频率不一致，混用会出现互相矛盾的数字。也**不要在同一批并行调用里同时调用两个 MCP**，以便节省 token。**报告正文和标题里不写数据来源。**

| 章节 | 数据源 | 主要工具 |
|---|---|---|
| 对象确认（子体对比、最畅销子体）| 仅卖家精灵 | `asin_detail`、`asin_sales_trend`（逐个子体取子体月销量）、`competitor_lookup`（子体价格、评分、小类排名）|
| Listing 生命周期：首次 Buy Box、首次 BSR、价格与销量月度轨迹 | 仅卖家精灵 | `keepa_info`、`asin_sales_trend` |
| 标题和主图变化 | 仅西柚 | `get_asin_info_change_trends` |
| 评论资产诊断 | 仅卖家精灵 | `review`（明细）和 `keepa_info` 的 `reviews`、`rating` 日序列 |
| 运营动作时间轴 | 价格、BSR、评论用卖家精灵（复用已取数据）；广告、关键词、流量用西柚 | — |
| 广告打法、投放词库 | 仅西柚 | `get_asin_ad_change_trends`、`get_parent_asin_ad_campaigns`、`get_parent_asin_ad_keywords`、`get_parent_asin_ad_campaign_detail`、`get_asin_keyword_count_trends`、`get_asin_keywords_daily`、`get_asin_keyword_rank_trends`、`get_asin_traffic_trends`、`get_keyword_advertising_replay`、`get_asin_keywords`、`get_asin_keywords_monthly` |

### 取数方式：交给便宜模型，Claude 不直接调用上表的工具

这些工具返回的序列和明细很长，进了 Claude 的上下文后，每一步都要重复计费。所以 Claude 只写调用清单、看统计、做判断（做法见 `batch-offload` skill）：

1. 每一轮，Claude 把要调的工具和参数写成 `WORK/calls_<轮次>.txt`，一行一个，例如 `tools["xydc-mcp"]["get_asin_keywords_daily"]({...})`。西柚的 `user_task`、`intent_summary` 也写进参数。
2. 按 MCP 选执行方，不用子 agent：

   | MCP | 执行方 | 命令 |
   |---|---|---|
   | 西柚 | DeepSeek（opencode） | `~/.claude/skills/batch-offload/scripts/oc_pull.sh WORK/calls_N.txt WORK/pull_N` |
   | 卖家精灵 | Gemini Flash（agy） | `~/.claude/skills/batch-offload/scripts/agy_pull.sh WORK/calls_N.txt WORK/pull_N` |

   - 卖家精灵 opencode 里没接（2026-10-30 实测报 Unknown tool），只能用 agy。参数写成 `{"request":{...}}`、`{"asin":...}` 这类工具原生格式。
   - 原始返回落盘到 `WORK/pull_N/raw/`，`index.json` 记录每个文件对应的工具和参数。
3. 拉完先看脚本打印的统计。`errors` 不为空时，把失败的行单独写成新清单**重跑一次**；仍失败的，Claude 自己调用或在报告的数据限制里写明，不反复重跑（西柚按次扣 Credits）。DeepSeek 偶尔第一次报 Unknown tool 又自己重试成功，以落盘文件为准。
4. Claude 写 Python 从 `WORK/pull_*/raw/` 里取需要的字段，只打印要用的表格和关键数字（如 D0、各节点价格、评论分类计数），不要 cat 原始 JSON。

建议分四轮：
- 第 1 轮（卖家精灵）：`asin_detail`，以及每个子体的 `asin_sales_trend` 和 `competitor_lookup`，用来确认分析对象（第三部分）。
- 第 2 轮（卖家精灵）：对象确定后，拉 `keepa_info` 和 `review`（翻页一并写进清单）。
- 第 3 轮（西柚）：D0 确定后，按分析窗口拉西柚的趋势和词表工具，加上 `get_asin_ad_change_trends`、窗口内的活动列表和按周活动列表（见 7.1）。
- 第 4 轮（西柚）：按 7.1 的规则，拉每个新活动开启后的活动内搜索词。

### 西柚 Credits 预估（2026-10-30 实测）

| 工具 | 单价 |
|---|---|
| `get_asin_ad_change_trends` | 7（一个窗口一次） |
| `get_parent_asin_ad_campaigns`、`get_parent_asin_ad_keywords`、`get_parent_asin_ad_campaign_detail` | 5（每次） |
| `get_asin_keywords`（page_size 1000） | 20 |
| `get_parent_asin_ad_campaign_trends` | 约 0.5 × 活动数 × 天数（14 个活动 × 64 天 = 490），默认不用 |

第 3、4 轮开拉前，用一句话告诉用户预计扣多少 Credits。一般首月复盘的广告部分在 100–200 之间。

“不要在同一批并行调用里同时调用两个 MCP”这条照旧，第 3 轮只放西柚。DeepSeek 和 agy 都跑不通时，Claude 才自己调用。

结论标记：默认就是直接数据，**不逐条标注**。只有推断结论标 `{推断:高|中|低}`，公开数据无法证明的标 `{无法确认}`；核心结论里可以用 `{直接}` 标出直接数据。

严禁虚构。历史截断时只能写“可查询历史中首次出现”。预估销量必须标“预估”。没有日级销量时不得拆分或虚构日销量；时间太久且没有日销量时，用 **BSR 中位数和最佳名次** 代替销量评估。匹配方式、预算、竞价、SKAG 一般只能推断。除非工具直接返回，不得把投放增强写成“提高预算或竞价”。

## 三、确认分析子体

查询全部父子体，比较：变体属性、价格、评分和评分数、**最新完整月子体销量**、小类 BSR、上架时间。

最畅销子体按最新完整月的子体销量判断。若输入 ASIN 不是最畅销子体，先输出对比表并暂停，询问用户：
- A. 继续分析输入 ASIN；
- B. 改为分析最畅销子体。

无变体时直接继续。同时记下目标是否是变体中**最早上架**的子体，第五部分会用到。

## 四、Listing 生命周期

查询当前的标题、品牌、价格、Coupon、评分、评论数、卖家、配送方式，以及：
1. 可查询历史中的首次 Buy Box 日期（D0），以及当天的价格、划线价、Coupon、评分、评论数、卖家。**首次 Buy Box 历史截断或不可用时，用首次小类 BSR 收录日替代 D0**，并在页面副标题里用一句话说明；
2. 首次小类 BSR 收录日期、类目路径及排名；
3. 价格与销量月度轨迹（子体和父体月销量、价格）；
4. 标题和主图历史变化。

目标日无记录时，使用最近一条记录，并注明实际日期和相差天数，标为“近似值”。父体组建的确切日期不需要确认，也不写进数据限制。

## 五、评论资产诊断

数据来源：`review` 工具的逐条明细（日期、星级、VP 和 Vine 标签、图片、视频、SKU），以及 `keepa_info` 的评分总数和平均分日序列。纯星级评价数 = 评分总数 − 可见文字评论数。只能拿到部分评论时，说明样本数量和日期范围，不得把样本当成全部评论。

评论标签只能写：Verified Purchase（VP）、Vine、疑似直评（未显示 VP 且非 Vine，不得认定为刷评或违规）、纯星级、无法确认。

**分工**：VP、Vine、星级、图片视频、日期这些结构化字段，用 Python 直接从 `review` 原始返回里统计，不交给任何模型转抄。评论**正文**有 30 条以上时，逐条读正文这件体力活交给子 agent `deepseek-offload`（做法见 `batch-offload` skill）：

1. 用 Python 把评论写成 `input.tsv`，一行一条，`评论id<TAB>标题 + 正文`。
2. 用 Agent 工具调用 `subagent_type: "deepseek-offload"`，要求每条输出 `{"id":..,"summary_zh":"<20 字内中文摘要>","product_mentioned":"<评论里描述的产品是什么，原词>","mismatch":true/false}`，其中 `mismatch` 指评论描述的产品和目标 ASIN 的产品明显不是同一种东西（目标产品的标题和品类写进指令）。
3. 回来后，Claude 用 Python 把 `summary_zh` 并回明细表，亲自抽查样本。

5.1 时间线的“内容摘要”可以引用 `summary_zh`，写进报告前 Claude 要读一遍原文核对。`mismatch` 只是 5.3 的线索，标为 true 的评论 Claude 必须逐条读原文、自己做相关性判断，不能直接采用。评论正文不到 30 条时，Claude 自己读。

本节只看首月评论资产。要做全部评论的问题和卖点打标、算占比，用 `mj-competitor-review-analysis`。

### 5.1 评论时间线

按日期从早到晚列表，**只逐行列关键日期**：首条评论、首条 VP、首条 Vine、首条疑似直评、首条视频评论、差评（3 星及以下）、评分数异常跳增或减少。其余日期按周合并成一行（例如“W2 其余：VP 5 条、Vine 2 条，均 5 星”）。全表控制在 10 行以内。

| 日期（D+N）| 事件 | 星级 | 图片视频 | 内容摘要 | 累计评分数（平均分）|
|---|---|---|---|---|---|

不单独写评分走势时间线，累计评分数和平均分已经在表里。视频评论要区分买家评论视频和 Listing、品牌、达人视频；没有历史快照时，只能写“当前可见含视频，附件实际添加日期无法确认”。异常增减只看分析窗口内。

### 5.2 首月评论构成

先给出 D+30 评分总数，再按类型拆分：

| 类型 | 条数 | 带图片 | 带视频 | 继承（早于 D0）|
|---|---:|---:|---:|---:|

类型行：VP、Vine、疑似直评、纯星级、合计。“D0 已有评论”就是“继承评论”，只列一次。表后用一两句写：评论净增量（D+30 评分总数 − D0 评分总数）、真实新增占比（窗口内可确认新发布评论数 ÷ D+30 评分总数）；明细不完整时标“可确认下限”。

### 5.3 老链接判断（多数情况不写）

**只有在 D0 前有评论，或窗口内评分数异常跳增时才写这一节**；目标是最早上架的子体且没有这些异常时，整节不出现，也不写“已省略”之类的说明。

需要写时，计算“评论领先天数 = D0 − 评论发布日期”：早 1–7 天可能是记录延迟；早 8–30 天结合标题、主图、类目、价格和父子体核查；早超过 30 天列为继承评论资产；早超过 90 天是强老评论信号。Buy Box 历史截断时写“早于可查询的首次 Buy Box”，不得写“早于首次销售”。逐条判断相关性（高度相关、部分相关、明显无关、无法判断），结论分四类：高度疑似合并无关老链接；相关老链接或老变体评论继承；证据不足；暂未发现。用一张 6 列以内的表呈现。

## 六、运营动作时间轴（按周卡片）

窗口：上架首月按周划分为 W1（D0～D+6）、W2（D+7～D+13）、W3（D+14～D+20）、W4（D+21～D+27）、W5（D+28～D+30）；最近 30 天模式从截止日期向前推 30 天，同样按周划分。

用 `weeks` 卡片呈现，每周固定这些项，每项一句话：
- 动作（同一轮连续动作合并；每天相同的 Coupon 不重复写）
- 价格促销
- BSR（中位数和最佳名次；没有日销量时用它代替销量）
- 广告（新增活动、新增投放词、广告流量占比）
- 关键词（自然词和广告词数量，核心词自然位和广告位）
- 评论（评分数变化、平均分、各类型新增）
- 评估：写进卡片底部 `verdict`，给评级和一句理由；价格、广告、评论同期变化时写“联合动作”

**第一个广告活动**在时间轴前用一段话单独写清楚：开启日期、广告类型、推测的投放方式和投放词（用 7.1 拉到的该活动开启后两周内的词，按 7.2 的规则推断）。广告活动不写 ID，写“第 1 个 SP 活动”这样的序号。

评级标准：
- 强：BSR、自然词、自然位中至少两项改善，且有保留；
- 中：活动期改善，结束后回落；
- 弱：只有短期流量或广告位改善；
- 负向：加强后自然位没有改善，广告依赖上升；
- 无法判断：数据不足或动作重叠。

## 七、广告打法（仅西柚）

时间范围：首月模式看 **D0～D+60**（首月刚结束时常有第一次大加码）；最近 30 天模式看这 30 天。

### 7.1 增投时间线（按活动）

西柚的父体广告活动工具能回溯一年内任意日期区间（实测可回到 11 个月前的上架首月），所以增投按**活动**来复盘，不再靠前后 7 天的词表差集去猜。

| 日期（D+N）| 新增活动 | 活动内词数 | 代表投放词 | 匹配推测 | 出现的周 |
|---|---|---|---|---|---|

取数（第 3、4 轮）：

1. **新增日期**：`get_asin_ad_change_trends`（`start_date` 取 D0−7，`end_date` 取窗口终点）。它逐日列出新观测到的活动 ID 和类型（SP、SB、SBV）。第一个活动可能早于 D0（实测有 D−3 的），照实写。
2. **活动清单和流量**：`get_parent_asin_ad_campaigns`，`cycleFilter` 设成整个窗口，`page_size` 100。用它的 `shareOfParentAdTraffic` 筛掉窗口内流量占比 <1% 的小活动（合并成一句“另有 N 个小活动”），其余进入下一步。
3. **出现的周**：对 W1、W2…到窗口终点的每一周，各拉一次活动列表（每周 5 Credits）。看每个活动在哪几周出现，首月内就停掉的测试活动也能看出来。按周列表单独放一个清单和目录（例如 `calls_weeks.txt` → `pull_weeks`），不要传给 `frame.py`，否则会覆盖整窗口的活动流量。
4. **活动内的词**：每个保留下来的活动拉一次 `get_parent_asin_ad_keywords`，带 `campaign_id`、`campaign_type`，`cycleFilter` 取该活动开启日到开启后第 13 天（不超过窗口终点），`page_size` 100，`hasMore` 时翻页。同时拉 `get_parent_asin_ad_campaign_detail`（同样的区间），看展示位分布。
5. 用 `mj-competitor-ads-frame` 的 `scripts/frame.py` 算指标和初判（同义词表、相关性用法见那个 skill），Claude 再按它第五节的规则逐个确认匹配方式。

合并规则：**相邻两个新活动开启日期相隔 ≤3 天**，就并成一轮写一行（例如“D+31～D+35 第 4–9 个 SP 和第 1 个 SB”）。

**老活动加词**：`get_asin_keyword_count_trends` 的广告词数单日跳增（例如比前 7 天均值多 50% 以上），但前后 3 天没有新活动时，单独写一行“老活动加词或放量”。这一行的新增词仍用 `get_asin_keywords_daily` 前后 7 天差集找。

活动日趋势 `get_parent_asin_ad_campaign_trends` 能精确到每天，但很贵（见成本表），只在用户要求精确停投日期时用。

### 7.2 匹配方式判断规则

全部按 `mj-competitor-ads-frame` 第五节的规则判断，不在这里另立规则。要点如下：
- 一个活动只有 1–3 个词且 Top1 占 ≥80% → 精准；
- 种子词根覆盖 ≥85% → 广泛（连续包含 ≥95% 为词组）；
- 几组种子合起来覆盖 ≥85% → 多个广泛词；
- 词散但相关 → 自动（紧密）；
- 不相关为主 → 自动（宽泛）、商品定位或手动投非本品词；
- SB、SBV 没有自动投放，但有主题定位。

第一个广告活动的说明（第六部分）也用这套结果。

单 ASIN 和多 ASIN：广告放映机样本里只看到一个 ASIN 时，写“样本内仅发现一个 ASIN”。广告放映机只支持 US、UK、DE，且只能查最近约 90 天；更早的日期改用广告位和流量趋势。SKAG-like 只能推断。

### 7.3 每次增投的效果（一张表）

所有增投轮次合进**一张表**，每轮只列 3 到 5 个代表投放词（核心词、新增词、低效扩量词各至少一个）：

| 增投 | 投放词 | 匹配推测 | 自然位（前→7天→14天）| 广告占比（前→7天→14天）| 结论 |
|---|---|---|---|---|---|

“增投”列只在每轮第一行写（例如“D+31 第 4–9 个 SP 和第 1 个 SB”）。表后为每一轮写一句话：BSR（前 7 天中位数 → 活动期最佳 → 后 7 天中位数）和评级。当前是否还在投放不在这里写，统一放在投放词库。

判断逻辑：广告上升后自然位持续提高 → 有效推自然位；广告上升但自然位不变 → 效率偏弱；广告占比下降而自然表现维持 → 完成自然承接；广告消失后自然位回落 → 广告依赖高；只有广告词增加，流量和自然位不增 → 疑似低效扩量；与降价、Coupon 或评论增长同期 → 联合效果。

**停投判定**：西柚只记录新增活动，没有停止状态。
- 活动级：按周活动列表里，某个活动从某周起不再出现，就写“约 W_ 后停投”；当前是否在投，看最近 7 天的活动列表（`period: last7days`）。
- 词级：某个词在最近 7 天内广告流量为 0，且没有任何广告位，判定为“已停投”。

## 八、投放词库（仅西柚，不按时间展开）

- 用一句话给出规模：当前在投活动 N 个（SP、SB、SBV 各几个，取最近 7 天活动列表）；曾投放过 N 个词，当前在投 N 个，已停投 N 个。
- **一张表**：核心词当前状态（默认 20 个，按自然流量排序），列为：关键词、自然位、当前广告位、广告占比、状态（在投、已停投、未投）。
- 两个列表：曾投放词按类别（核心品类、属性规格、功能场景、竞品品牌、跨品类、其他语种）各举 5 个左右代表词并给出词数；已停投词按累计广告流量列前 15 个。

### 9.2 写作规则

1. 基础字段每个单独一格；全文不用“/”连接两个概念，改用“和”“、”“或”或拆成两项。
2. 括号里不放次要细节（例如数据更新时间）。
3. 没有异常的章节和段落直接不写，也不写“已省略”。
4. 每节最多一张表（第五部分评论资产除外，最多两张），每张表最多 6 列；每节文字结论不超过三句。
5. 不写读者用不上的内部代号：广告活动 ID 写成序号；SOR 等工具口径第一次出现时注明一次。
6. 总字数（不含图表数据）上限 **20,000 字**，按内容需要控制。

### 9.3 生成和发布

1. 按 `references/report-data.md` 的格式写数据文件，保存在当前工作目录，例如 `<品牌>_<ASIN>_report.json`。完整示例见 `references/example-data.json`。走势图的日数据用 `keepa_info` 的日表生成，不要手抄。
2. 运行 `python3 -I <skill 目录>/scripts/build_report.py <data.json> <out.html>`，脚本会输出可见字数，超过 20,000 字时会提示精简。
3. 发布前按 Artifact 工具的要求加载 `artifact-design` skill；模板已经符合页面规范，不需要再改设计。然后用 Artifact 工具发布 `out.html`：首次发布带 `icon: "chart"` 和一句话 `description`。同一 ASIN 重跑时用同一个文件路径重新发布，链接保持不变。
4. 回复里给出链接，再用三五句话概括核心结论。

## 十、强制红线

- 评论早于 D0 不等于一定合并；相关老评论也不能算作新品新增；
- 只有“无关早期评论 + 评论跳增或 Listing、变体变化”同时出现，才是强合并信号；
- 未显示 VP 不等于直评或刷评；当前含视频不代表视频是在评论日上传的；
- 父体共享的评论不能全部算作目标子体的自然积累；
- 多项动作同期发生时，只能评价联合效果；
- 所有重要结论都必须附日期、数值、关键词或评论证据。

## 十一、工具注意事项（实测）

- `keepa_info`：不传时间时只返回最近约 180 天，必须传 `startTimestamp`（例如上架前一个月）才能拿到 D0 附近的数据。结果常常超长，会落到文件里，用 python 解析成日表；建议 `dailyLatest: true`，并只要 `price,buyBox,priceList,buyBoxSellerIdHistory,bsr,subSalesRank,reviews,rating,sellers` 这些字段。
- `review`：每页最多 20 条，`startTimestamp/endTimestamp` 实测不生效；按页翻到最后几页即可拿到最早的评论。可以用 `typeList` 筛选：`[3]` VP、`[4]` Vine、`[2]` 视频、`[1]` 图片。相邻页偶尔有 1 条重复，计数时要去重。
- `asin_sales_trend`：会返回 `parentUnitSales` 和 `childUnitSales`，子体月销量要逐个子体查询。
- 西柚 `get_asin_keywords_daily`：单次最多 30 天（含首尾）。`page_size` 100 的结果常常不超长，会直接进入上下文，很耗 token。先看小页结果里 `searchTermCount` 的 advertising 数，`page_size` 设成刚好覆盖广告词数即可（按 `advertisingTraffic` 排序时，广告词都排在前面）。
- 西柚 `get_asin_keywords_monthly`：`start_month`～`end_month` 跨多个月时，返回的是整个区间汇总后的一张词表。按 `advertisingTraffic` 降序、`page_size` 1000 拉一次，就能拿到上架至今“曾投放过的词”。字段 `trafficAcquisitionRate` 在 `trafficSummary` 下面。
- 停投判定用 `get_asin_keywords`（近 7 天）全量拉取（`page_size` 1000，结果会落到文件里），再和月度汇总词表做差集。
- 西柚 `get_keyword_advertising_replay`：只能查最近约 90 天。
- 西柚 `get_asin_keyword_count_trends`：结果很长，会落到文件里，用 python 汇总每天的 organic/advertising 和各广告位的词数。
- 西柚 `get_asin_ad_change_trends`：可用日期从 2024-06 起；返回 `trends[].added[]`，含 `campaignId`、`campaignName`、`campaignType`。
- 西柚父体广告活动工具（`get_parent_asin_ad_campaigns`、`_keywords`、`_campaign_detail`）：输入任一子体 ASIN，自动解析父体；`cycleFilter` 用 `startDate`、`endDate`，最长 365 天；活动 ID 和 `get_asin_ad_change_trends` 的 `campaignId` 一致，可以直接对上。
- 卖家精灵在 opencode 里调不到，统一用 `agy_pull.sh` 拉；`asin_detail` 的参数是 `{"asin":...,"marketplace":...}`，不要包 `request`。
- Bash 里不要把多个路径放进一个变量再传给脚本（zsh 不拆分），直接写路径。
