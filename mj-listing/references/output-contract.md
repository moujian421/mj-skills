# Listing 交付合同

不得只给原则、分数或一段“优化后文案”。核心四块每次必交；可选块按任务需要输出，没做的在结论里写一句“未做/原因”，不必逐节填 `NOT AVAILABLE`。

默认交付到飞书表格：一个「文案」sheet 放核心块 1，一个「审核」sheet 放核心块 2–4 和可选块。用中文沟通，写完回读关键单元格。

## 结论卡（放在审核 sheet 顶部）

- 对象：`marketplace / ASIN / SKU / 型号`
- 模式：`DRAFT | DIAGNOSE`
- 状态：`READY FOR REVIEW | DRAFT | HOLD`
- 主目标：只写一个
- 主问题：最多三项
- 阻塞项：没有则写 `None for review; 上传仍需人工批准`；类目模板未核对时写“按用户要求不核对”

## 核心 1：文案表

每个字段一行：

| 款式 | 字段 | 英文文案 | 中文释义 | 长度 | 上限 | 声明 ID | 依据 / 备注 |
|---|---|---|---|---|---|---|---|

字段依次为：Title（Item name）、Item highlights、五点 1–5、Backend Search Terms。

- Title ≤75 字符；Item highlights 为一个逗号短语字段，≤125 字符，合计 ≤200；五点每条 10–254 字符；后台词按 UTF-8 bytes 计，≤249 bytes。以当次联网核对的规则为准。
- 备注写清关键词来源（哪份表、哪一行、搜索量），自己拼的短语注明“拼接”，查不到量的说法注明“无搜索量”，功能写法注明参照的竞品。
- 表底列出规则依据（来源链接 + 核对日期）和本次状态。
- 有旧文案时，新旧并列，并说明删改原因。

## 核心 2：证据清单与声明账本

| 证据 ID | 证据内容 | 适用款式 | 等级 | 已核实 | 来源（文件名/聊天记录/日期） |
|---|---|---|---|---|---|

| 声明 ID | 拟写声明 | 适用款式 | 证据 ID | 状态 | 允许字段 |
|---|---|---|---|---|---|

状态：`VERIFIED / NEEDS_EVIDENCE / REJECTED`。`NEEDS_EVIDENCE` 和 `REJECTED` 不得进入终稿。用户确认的事实写“用户确认 + 日期”，并保留工厂原文。

## 核心 3：关键词映射

| 关键词 | 月搜索量 / 购买率 | 各款覆盖位置 | 决策 | 来源 |
|---|---|---|---|---|

决策：`TITLE / HIGHLIGHTS / BULLET / BACKEND / ATTRIBUTE / AD-ONLY / EXCLUDE / INSUFFICIENT-SAMPLE`。竞品品牌词只能是 `AD-ONLY`。

## 核心 4：图片 / A+ / 视频 Brief

| 槽位 | 主信息 | 各款内容 | 必拍 / 禁用 | alt text |
|---|---|---|---|---|

每张素材只讲一件事；主图守类目规则；不随货的道具要标注；AI 场景不得改变商品结构、颜色或配件。详细方法见 `creative-and-conversion.md`。

## 可选块

按需输出，格式从简：

- **购买问题矩阵**：消费者问题、回答位置、是否已回答、预期减少的摩擦。
- **漏斗诊断**（老品有数据时）：层级、观察、证据、可能解释、已排除、建议动作、预期指标。
- **描述 / A+ 可读取正文**：完整正文，标出配合的图片位置和不能写的声明。
- **属性**：属性名、旧值、新值、依据；需与文案一致（如材质）。
- **变体一致性**：父体不携带子体独有事实。
- **广告联动**：哪些词只投广告；Listing 实验期间冻结哪些广告变量。
- **实验卡**（上线后有流量时）：假设、类型（MYE 单属性/多属性/前后分时）、主指标、护栏、冻结变量、停止规则、结论强度。
- **审计结果**：`audit_listing.py` 状态和主要检查项。

## 最终状态定义

- `READY FOR REVIEW`：文案、证据和规则检查齐全，可供人审；仍未批准上传。
- `DRAFT`：方向可讨论，但存在非关键数据或素材缺口。
- `HOLD`：关键事实、用户要求的规则核对或合规证据不足，不能上传。
