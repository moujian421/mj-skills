# MJ-Picture 图片需求

给设计看的图片需求表。文案、卖点和事实证据沿用 `mj-listing` 的规则（只写实物有的、每个卖点有依据）；本 skill 管图片怎么分工、每张图上写什么、怎么写。Claude 不生成图片；要用 AI 生图的图位，在表里写好提示词交给设计。

图片的目标只有一个：卖得更好。按顺序是吸引点击、传递卖点、打消顾虑、促成下单，每张图都要能说清它在这条链上负责哪一环。

## 文件怎么用

本文件只放跨品类通用的规则。

**底线和默认**：标【底线】的规则违反了会违规、写错事实或误导买家，必须守，脚本报「错误」。其他规则都是默认做法，多数情况照做；有理由不按时，在「依据」或「禁用 / 注意」写一句理由就行，脚本只「提醒」。

## 流程

1. **收集事实。**【底线】至少要有实拍产品图和 Listing（标题、五点、描述），没有就先找用户要，不开始排图位。再收集说明书、出货检验报告零件清单、外箱标签、工厂尺寸图、样品视频、用户确认的聊天记录。随货配件以零件清单为准。每条事实标成三类：**已确认**（资料里看得到或用户明确说过）、**待确认**（创意上的建议，等用户点头）、**未知**（缺资料，会影响画面或说法）。未知的不画、不写，列出来一次问用户；不能只凭竞品图推断我方有什么部件、材质、尺寸或认证。
2. **看竞品图和评论。** 头部竞品主图 + 副图 + A+ 逐张记录讲了什么卖点、什么构图，写进「竞品图片参考」。只学信息顺序和构图结构，不抄图片、文案、图标。再看头部竞品的 1–3 星评论，记下高频顾虑，作为痛点对比图、尺寸图和细节图的依据；买家常用的说法可以借来写标题，但不能把评论原话放进图里。评论 30 条以上时按全局规则交给 DeepSeek 打标签，Claude 抽查后再下结论。
3. **产品分析**：用几行写清产品定位、核心用户、购买动机、主要使用场景、差异化优势（每条注明来源：Listing、评论、搜索词、竞品统计）。一级差异从这里定。
4. **排图位大纲**：按「卖点排序」排，每个图位写一行“图位｜类型｜本张要回答的买家问题｜要打消的顾虑”，表头「顺序依据」行写清依据；读对应的品类文件，没有就按竞品统计排。用「买家问题清单」查漏。**大纲先给用户确认**，确认后再逐张写。
5. **逐张写需求**：先写成 `brief.json`（格式见 brief-schema.md），文案按 copy-rules.md、A+ 按 aplus.md，AI 图位的提示词按 ai-image-prompts.md。
6. **配参考图**：默认每张 2 张竞品图 + 我方素材（见「参考图」）。
7. **跑检查脚本** `scripts/brief_lint.py`：「错误」全部改完，「提醒」逐条按意思判断；再做「Claude 自查」。
8. **拍摄清单**：脚本生成的 `shoot_list.tsv` 补上角度、背景、优先级（见「拍摄清单」）。
9. **写入飞书**：用脚本生成的 `writes.json` 一次 `--writes` 批量提交，不逐格写；排版用 `table-display-optimization`；写完只回读改动的格子核对。状态标 DRAFT，等设计和用户确认。设计出稿后按「设计稿审核」分三关审。

**审核已有的表**：用 `scripts/sheet_to_brief.py` 把飞书表转成 brief.json，再跑检查脚本，把错误和 Claude 自查的问题一起列给用户，改不改由用户定。

## Argon 参与的节点

用户要求（2026-10-28）：每个需要判断的节点都找 agy 的 Argon（`gemini-4-argon-medium`）要第二意见，调用方法按 `batch-offload` skill 的「决策思考型任务」。

| 节点 | 交给 Argon 的 | 怎么问 |
|---|---|---|
| 产品分析 + 一级差异（流程 3） | 事实摘要、评论和搜索词统计、竞品统计 | 先不给 Claude 的结论，要它独立给定位、动机和一级差异 |
| 图位大纲（流程 4，给用户确认之前） | Claude 的大纲 + 依据 | 挑刺：顺序、漏掉的买家问题、重复的任务 |
| 整套需求初稿（流程 7 之后） | 每张图的文案、类型、画面要点 | 挑刺：意思重复、好处空泛、动词和实物不符、合规风险 |
| 审核已有的表 | 脚本结果 + Claude 的判断 | 挑刺：哪些提醒该改、哪些可以不改 |
| 改规则 | 规则原文 + 用户的纠正 | 分类：底线 / 默认 / 品类专属，有没有更好的写法 |

- 只给精简后的事实，不给整张表；要求它补的假设标【假设】，Claude 逐条核对后才采纳。
- 结论由 Claude 下，给用户的结果里用一句话说明采纳了 Argon 哪些意见、哪些有分歧、为什么。
- agy 不通或额度用完时，Claude 自己完成并说明。

## 卖点排序

1. **主图只管识别。** 搜索结果里一眼认出是什么、买到什么。
2. **先差异，后基础。** 一级差异（这款比一般竞品多的点，或用户指定的核心卖点）紧跟主图；竞品人人都有的基本配置往后放。
3. **刚需问题放前段。** 竞品几乎都讲、放在前 2–4 张的问题，是买家刚需，紧跟一级差异。如果差评或退货里它是高频问题，可以提到一级差异之间。
4. **再讲使用体验。** 顺不顺手、稳不稳。
5. **尺寸规格放后面。** 下单前最后核对，防止买错。
6. **实景收尾。** 带出整体感受，可选。
7. **和五点顺序一致。** 买家看图和读五点时信息对得上。

**买家问题清单**（查漏用，不是固定图位）：整套图和 A+ 要能回答——为什么买它？怎么用？适不适合我（尺寸、规格）？比别家好在哪？真实用起来什么样？为什么放心买？最后一个问题只用有证书编号的认证、测试数据、材质证明回答，不写保修退换、No.1 这类说法。

依据来自竞品统计：在「竞品图片参考」里逐张记录头部竞品图 1–9 讲了什么，最后一行写“规律”，用“x/7 家有、多在第几张”计数。A+ 也做一遍（开场、哪些重复副图、哪些只在 A+ 出现）。一级差异要写明来源（用户指定、搜索词、评论数据）；没有依据时先向用户确认。

## 表结构

表头前几行固定写：尺寸、文案层级与字数上限、顺序依据、通用要求。

副图表列：

```
图位 | 尺寸 | 本张要回答的问题 | 主标题 Headline | 副标题 Sub-headline | 小文案 Body | 图标 Icons |
竞品参考图 | 竞品参考图 2 | 我方 / 其他参考图 |
字数（词 / 字符）| 中文释义 | 画面与构图 | 必拍细节 | 禁用 / 注意 | 参考竞品图 | 依据 | 参考图说明
```

三列参考图紧跟在文案列后面，设计看文案时就能对照图。A+ 表的额外列见 aplus.md。有 AI 生成或实拍合成的图位时，在最后加一列「AI 生图提示词（可选）」，其他图位填“—”。

「本张要回答的问题」写成“买家问题 → 本张怎么回答”，让设计知道这张图为什么这样排，例如“折叠后放得进后备箱吗 → 折叠步骤 + 后备箱实拍”。

「画面与构图」第一行写制作方式：实拍 / 实拍合成 / AI 生成，审稿时按这个决定重点核对什么。不放的层级格子填“—”。字数列由脚本生成。

## 尺寸与文件

- **主图**【底线】：1600×1600 px，纯白底 RGB 255,255,255，背景没有灰影或色块（商品脚下自然的接触阴影可以），商品完整展示、不裁切，占画面 85%–95%，不放任何文字、图标、水印、徽章、场景，不放不随货的东西。用实拍图，AI 只能做局部修改（补光、阴影、去杂物），不能重绘商品。
- **副图**：1200×1500 px（4:5 竖图），关键文字离边缘 ≥80 px，手机上缩小后仍能看清。
- **A+**：见 aplus.md。
- **文件**：JPEG（或 PNG），sRGB，单张 ≤10 MB；主图和副图最长边 ≥1000 px 才能放大查看。文件名 `ASIN.MAIN.jpg`、`ASIN.PT01.jpg`…`ASIN.PT08.jpg`，「图位」列可同时写 MAIN / PT01。规格以 Seller Central 最新图片要求为准。

## 参考图

- **参考图列只放同类目竞品图。** 「视觉风格参考」里的品牌只用来定整体风格，写进「通用要求」或「画面与构图」，不把其他类目的图放进参考图列。
- **竞品参考图默认每张 2 张**（含 A+ 每个模块），最好来自不同竞品，第 2 张补第 1 张没讲到的点。飞书一个格子只能嵌一张图，所以分两列各嵌一张。主图，以及竞品都没讲过的独有卖点，可以只放 1 张，在「参考图说明」写明原因。
- 「参考竞品图」写成“竞品名 #图号（参考点）”；「参考图说明」写成“竞品①：…｜竞品②：…｜我方：…”，和我方不一样的地方写明只参考版式。
- 补图前先下载格子里现有的图看一眼，确认是哪家哪张，避免两列放同一张。
- **「我方 / 其他参考图」列只放我方素材**【底线】（说明书、工厂图、样品照片、视频截图）。没有时不拿竞品图顶上，写“无（需另拍…）”。同一卖点在副图里已有我方图时，A+ 可以直接复用。
- 竞品图实在找不到第 2 张时，写明原因并告诉用户。网页表格形式的 A+ 对比表可按页面内容重建后截图，标注“重建截图，只参考版式”。

## 证据冲突【底线】

资料之间说法不一致时，以用户最新确认为准；「依据」列把两种说法和确认日期都记下来，交付时提醒用户同步改说明书等资料。没有用户确认时不自行二选一，先问。

## 通用要求

- 【底线】不随货的东西出现在画面里时，加角标 Not included。
- 【底线】所有卖点必须是实物有的；在“禁用 / 注意”列写清这款不能写的说法，并写进 brief 的 `banned_claims`。
- 每张图只讲一件事，图与图之间不重复任务；图和五点互相印证，但文字不逐句照搬。
- 全套用同一套字体和品牌色。
- 【底线】AI 场景图不得改变商品结构、比例、尺寸、颜色、材质、零件、Logo 和标签文字，实拍商品图是唯一标准。AI 图和合成图最容易错在手、反光、阴影、透明件、包装上的字和小配件，审稿时逐项对照实物。不生成商品做不到或不安全的用法，不做夸张或虚假的效果（如夸大的弹跳、不存在的功能演示）。提示词写法见 ai-image-prompts.md。
- 尺寸参照（人、手、车、常见物品）按真实比例摆，和尺寸图的数字对得上。
- 【底线】实景图里的人物、场地、他人商品或商标要有使用授权；拿不准就换素材。
- 文字和背景对比度 ≥4.5:1，文字不压在杂乱背景上。
- 【底线】不写 No.1 / best / premium、竞品品牌、价格促销。
- 「依据」列写到具体出处：说明书图号、视频时间点、工厂资料文件名、用户确认日期。

## 视觉风格参考（可选）

12 个品牌的视觉做法按大类整理在 [references/style-index.md](references/style-index.md)。只是参考，不是规则：先找最接近的大类，挑适合的手法用，不照搬构图、配色、图标和文案；本 skill 的规则优先。参考图列仍只放同类目竞品图，品牌风格写成文字要求。

## 拍摄清单

脚本把“需另拍”汇总进 `shoot_list.tsv`，整理成一张清单交给摄影或工厂一次拍完。每行补齐：用在哪张图、拍什么、角度和背景、必拍细节、是否需要人或场景、优先级。按下面几类查漏：

- 整机：白底正面、45°、背面（主图和 A+ 开场用）；
- 细节特写：每个一级差异部件、操作中的状态（如锁定前后）；
- 尺寸参照：展开、折叠（如适用），和常见物体或人一起；
- 配件：全部随货配件平铺一张，和零件清单逐项对；
- 包装：外箱和开箱内容；
- 场景：主要使用场景 + 次要场景，不随货物品标 Not included。

## 设计稿审核

设计出稿后分三关审，每关都过了再进下一关：

1. **需求确认**：事实、卖点、说法和画面方向，用户确认后才交设计（状态从 DRAFT 改为已确认）。
2. **初稿**：商品还原度（结构、颜色、配件、Logo 和实物一致）、构图是否按需求、手机端缩到 375 px 宽时文字和数字能不能一眼读清。
3. **终稿**：平台合规（主图规则、A+ 额外禁止项）、颜色和变体对不对、导出尺寸 / 格式 / 文件名。

每关的问题写回「禁用 / 注意」列或单独记一行，注明哪一关、哪张图。

## Claude 自查（脚本查不了的）

- [ ] 副标题、小文案和主标题没有**意思上**的重复；小文案没有复述画面已展示的操作（脚本只查字面）；
- [ ] 每张功能图都能说出“好处”和“场景”，不是只报参数；
- [ ] 动词和实物操作一致（看说明书或视频）；
- [ ] 中文释义和英文一一对应，不增不减；
- [ ] 每个卖点有依据，资料冲突已按「证据冲突」处理；没有“未知”状态的事实出现在画面或文案里；
- [ ] 配件清单名字是买家最能理解的叫法，同一部件只列一次；
- [ ] 画面里的不随货物品都写进了 `props`；尺寸参照按真实比例；
- [ ] 没按默认规则做的地方，都写了一句理由；
- [ ] 两列竞品参考图确认过是哪家哪张；品牌风格只写成文字要求；
- [ ] 主图无文字，副图关键文字离边 ≥80 px；文件规格和文件名已写明；
- [ ] 写入后回读改动的格子核对。

## 改规则之前

用户指出一个错误时，按顺序问三个问题，再决定写到哪里：

1. **能写成脚本检查吗？** 能就改 `scripts/brief_lint.py`，不往文字规则里加。
2. **只是这个品类或这一款的问题吗？** 是就写进对应的 `category-*.md` 或这款的事实表。
3. **能并进已有的原则吗？** 能就改那条，不新加。

三个都不是，才加进本文件或 copy-rules.md / aplus.md。新规则默认是“默认做法”，只有违反会违规、写错事实或误导买家的才标【底线】。例子放 examples 文件，不写进规则正文。每次改动在 changelog.md 记一行来源。本文件控制在约 18KB 以内，超过就先合并、删减。
