# 亚马逊全类目市场调研流程（mj-market-analysis）

将任意亚马逊品类的调研需求，转化为结构标准、数据交叉核验、结论可落地的 5 章飞书立项调研报告（1.市场大盘 → 2.竞品分析 → 3.VOS流量分析 → 4.VOC痛点分析 → 5.总结与立项建议）。

## 执行分工（用户 2026-10-26 指定，本 skill 一律照此执行）

| 角色 | 做什么 | 怎么调 |
| :--- | :--- | :--- |
| **Claude** | 定调用清单（工具名 + 严格 JSON 参数）、收费步骤找用户确认、用 Python 汇总原始数据成精简事实摘要、核对 Argon 草稿里的每个数字和【假设】、提审核意见、写飞书并回读 | — |
| **Gemini Flash（agy `gemini-3.8-flash-low`，2026-10-26 三档实测后选定）** | 所有 MCP 拉数（Sorftime / 卖家精灵 / 西柚），只按清单原样调用、只回“完成” | `~/.claude/skills/batch-offload/scripts/agy_pull.sh calls.txt OUT_DIR`；清单每行 `server / tool : {JSON}`；统计里 `errors`、`missing_lines`、`unexpected_calls`、`failed_batches` 都为空才算完整 |
| **Argon（agy `gemini-4-argon-medium`）** | 主导写报告：拿 Claude 的事实摘要写 5 章初稿和立项结论；收到 Claude 审核意见后逐条决定采纳与否并改稿 | brief 写法见 batch-offload「决策思考型任务」；只给摘要不给原始大数据，禁止它调工具 |

- 本 skill 里拉数不走 DeepSeek（`oc_pull.sh`）；Flash 不通时才退回 `oc_pull.sh`，并在结果里说明。
- 依赖上一轮返回的调用（先拿西柚 `resourceId`、先拿头部 ASIN 再查流量/评论）分轮跑，每轮之间由 Claude 从 `OUT_DIR/raw/` 里取参数写下一轮清单。
- 数字以原始返回为准：Argon 稿里的数和摘要对不上、或【假设】与事实冲突时，Claude 直接指出必须改，这类事实错误不交给 Argon 决定。
- 差评 ≥30 条的打标仍按全局规则交 `deepseek-offload` 子 agent（DeepSeek 免费额度用完时它会自动改用 agy Flash），Claude 抽查 5–10%。
- 西柚类目资源（500 Credits）同任务只生成一次；趋势类接口按“每 6 个月 5 Credits”计，近 33 个月约 30 Credits/个，预估清单时按这个算。

## 报告写法（用户 2026-10-27 反馈，必须遵守）

- **数据来源只写平台**：每小节末尾一行“> 数据来源：西柚、Sorftime（采集日期：YYYY-MM-DD）”，只出现 Sorftime / 西柚 / 卖家精灵（和“亚马逊后台商机探测器（待补）”）。正文也不出现接口名或字段名（`get_xxx`、`category_trend`、`cr10`、`avgCvr` 等），改成中文说法。
- **不重复**：同一个数字只在最合适的小节出现一次，别处引用结论。头部集中度（品牌/卖家/商品 Top3、Top10、Top20）只写在 1.2.1，2.2 不再写。
- **要有图**：
  - Argon 写稿时同时给出图表清单 JSON（`id / title / type / datasets / series / section`），在报告里用 `![图N 标题](charts/figN.png)` 占位，图下一句斜体解读；一般 8–14 张。
  - 图由 Claude 用 Python 直接读原始返回生成，数字不经任何模型转抄。
  - **飞书里的图必须可交互**（用户 2026-10-29 要求：鼠标悬停能看到每个柱子/点的具体数值）：每张图导出成一个独立 HTML（`references/minichart.js` 轻量 SVG 图表库，无外部依赖，单图约 10KB），写进飞书文档时用 `<html5-block path="@./figN.html"/>`（XML 格式创建/更新文档）。导出脚本参考 `references/charts_html_example.py`：每张图一个 spec（`panels` 里每个子图写 `type`=bar/stack/line/hbar、`categories`、`series`），只在悬停里显示的辅助数值用 `kind:'none'` 的系列，补充说明放 `extra`。2026-10-29 已在飞书实测：脚本可运行、悬停正常、`html-box-height-mode=auto` 高度自动撑开。HTML 单块上限 500KB。
  - 本地 Markdown 预览仍可用 PNG（`references/charts_example.py`），但交付到飞书一律用交互 HTML。
  - 先加载 `dataviz` skill。不画双纵轴：两个量纲不同的系列改成上下两张小图；网格线放在柱子下面；每张图左下角注明来源平台和采集日期。
  - **图型规则（用户 2026-10-27 指定）**：销量、销售额一律柱状图（多系列用堆叠柱）；搜索量的时间变化用**月度**折线（周数据先按月汇总，去掉首尾不完整月）；**销量占比用折线**——分类分布图里“商品数/商品数占比”用柱、“销量占比”用同一纵轴的折线叠在上面；占比随时间的变化也用折线。
  - Google Trends 除了近 5 年总览，再单独画一张**近 24 个月逐月**折线，每个点标数值。
  - 数值标注加白底，峰值标在点上方、谷底标在点下方，靠近横轴的点一律标在上方，不能压线或压到横轴文字；图例放到图外下方。
  - 左右并排放不下就上下排（宁可图高一点）。
  - 品牌份额图的每个品牌后面写上代表 ASIN（该品牌近 30 天销量最高的商品）；已拉的榜单里找不到的，用西柚销量榜按品牌筛选补拉（约 5 Credits / 5 个 ASIN），“Generic”写“多个无品牌商品”。
  - 两家平台口径不同导致结论不同时（例如卖家精灵节点 Top100 混有旅行包/戒指盒，西柚类目只含桌面首饰盒），把两家放在同一张图上下对照，并在解读里写清原因。
  - 生成后逐张打开看：标签重叠、图例压住数据、刻度难读都要修。

## Google Trends 州分布（2026-10-30 实测）

- 卖家精灵的 Google Trends 接口只有全国时间序列，没有州分布。agy 的 Gemini 在这个环境里只有网页搜索、没有读网页的工具，也不允许执行本机命令，拿不到州数值（会如实返回“拿不到”）。
- 做法：本机跑 `references/fetch_google_trends_states.py`（直接请求 Google Trends 网页背后的接口，不经过模型），取近 12 个月和近 5 年两份；再用浏览器打开 Google Trends 页面抽查前 5 名是否一致。页面上的“Related queries / Rising”顺手读出来，能发现站外热点（如动漫 IP 周边）。
- 解读：剔除人口很少、值为 100 且远超第二名的州（如怀俄明），作为异常值单独注明；其余州差距在约 10 分以内的，写“无明显区域差异”，不硬编区域场景。站外热度冲高而站内搜索不涨的，不能当旺季备货依据。

## 一、 第 0 步：找类目确认与收费调用审批

在拉取付费或大批量数据前，必须严格按以下两阶段与用户交互确认：

1. **阶段 A：免费检索候选类目节点并确认基础信息**
   - 先调用免费的 **Sorftime** `category_name_search` 和 **西柚（`xydc`）** `search_market_insight_categories` 查找候选叶子类目节点（NodeID / CategoryID）。
   - 向用户发起一次简短确认：
     - 目标站点（如 US/UK/DE）、确认最终选定的叶子类目节点路径与 ID。
     - 1～3 个核心大词（如 `golf push cart`）、延伸关联词（如配件词 `golf cart battery`）及我方目标价格带。
     - **飞书交付位置**：询问报告文档及附属表格存放的目标飞书知识库（Wiki）或文件夹路径。
     - **后台商机探测器（POE）数据**：询问用户是否已导出/截图后台 POE 数据（细分市场近 360 天搜索词表现、买家评论洞察、退货洞察）。明确告知：未提供的 POE 专属小节将保留标题并留空标注 `【待补：需后台商机探测器截图/导出】`，同时在下方另起一段**“【三方数据】”**用 API 数据给出对应分析结论。
2. **阶段 B：西柚（`xydc`）收费调用清单与 Credits 预估审批**
   - 首次执行西柚类目洞察前，必须先读取 Resource `xiyou://guides/category-insight-workflow-v2`。
   - 节点确认后，列出本次拟调用的 `xydc` 收费接口清单及预估消耗 Credits（如 `generate_category_insight_resource` 生成 `resourceId` 并在同任务全程复用；`get_category_keywords` 按月返回、每 20 个词收 1 Credit），经用户确认后再执行。
   - **调用铁律**：每次调用 `xydc` 工具时，`user_task` 参数必须**逐字填写用户原话**且同一任务内保持完全一致，同时填写清晰的 `intent_summary`。

> **相邻 Skill 与分流协同边界**：
> - **直接调用 vs 批量卸载（`batch-offload`）**：所有章节的拉数都按“执行分工”写成清单交给 Gemini Flash（`agy_pull.sh`），每章能并行的调用合在一轮；只有一两次很小的探路查询（例如确认参数格式）Claude 可以自己调。
> - **评论打标分流**：拉取 1～3 星差评满 30 条以上一律交由 **DeepSeek** 批量打标归类与翻译，Claude 抽查 **5–10%** 的原始评论核验标签准确性并下达工程归因判断。
> - **后续深挖路由**：深度扩词交 `amazon-keyword-seo` / `mj-keyword`；精细利润与 FBA 测算交 `amazon-fba-profit-ops`；Listing 与视觉落地交 `mj-listing` / `mj-picture`；飞书表格美化交 `table-display-optimization`。

## 二、 数据源分工铁律与口径准则

1. **主/辅数据源分工铁律（严禁三家平铺）**：
   - **关键词相关数据一律以西柚（`xydc`）为准**：核心词周搜索量、ABA 排名、搜索转化率、Top3 ASIN 点击/转化份额、流量入口词表、品牌词搜索量与排名等，全部以 `xydc` 为主数据源；卖家精灵（`sellersprite`）/ `sorftime` 仅作跨年趋势或 Google Trends 补充。
   - **市场大盘与竞品数据以 `Sorftime` 为主、卖家精灵（`sellersprite`）为辅**：大盘销量/销售额趋势、集中度、价格统计、上架时间、卖家所属地、配送方式、均价/星级趋势、退货率等，优先取 `Sorftime`（`category_report` / `category_trend`）；`Sorftime` 未覆盖的细分分层（如 Top10/Top20 集中度、细分上架时间段、FBA/FBM 评分对比、A+ 分布）用 `sellersprite` 或 `xydc` 补充。
2. **严禁冒充后台数据 & 三方数据必补齐**：
   - 拿不到的后台 POE 数据或缺失的区域分布数据，原小节保留标题并写 `【待补：需后台商机探测器截图/导出】`（或对应缺失说明）留空，绝不用三方数据冒充。
   - 凡是 `Sorftime` / `sellersprite` / `xydc` 有接口能取到的指标，报告中必须给出具体数值与结论，严禁留空或只写“见图”。报告中的原 `[图]` 位置统一由 Claude 用拉取的数据制成 Markdown 表格（必要时用脚本生成图表图片插入）。
3. **时间口径与精简溯源标注**：
   - 报告开头统一注明 **`数据截至 YYYY-MM-DD | 站点：{AMZ_SITE}`**。计算同比时**只比较相同月份区间**（如今年 1–9 月 vs 去年 1–9 月）；季节性分析**至少回看 24 个月**。
   - 不在每句话后啰嗦内联标注来源，改为**每个小节末尾统一单列一行** `> 数据来源：{主/辅工具及接口名}（数据区间/采集日期）`；仅在属于业务推演或孤证异常的句子末尾单独标注 `[推断]` 或 `[待核实]`。

4. **三方数据交叉核对（必做，数据拉完、写稿之前完成）**

   看的是**结论和趋势**，不是逐个数字。数值高低本来就会因为估算模型不同而不一样，只要结论一致就不用管；要查的是这类情况：同一个问题，两家平台给出的答案不一样。由 Claude 判断哪些差异会影响结论，只查这些。

   **重点对比的结论**（每项看两家以上平台给出的答案是否一致）：
   - 主流价格带在哪（例如一家说 $34–39，另一家说 $5–15）
   - 大盘在涨还是在跌，近期是否转弱
   - 旺季、淡季是哪几个月
   - 头部是谁、垄断程度高还是低
   - 新品有没有机会（新品销量占比的高低和走向）
   - 评论门槛高还是低
   - 对标竞品在涨还是在跌

   **数字差但结论一样的**：不用查，正文写清用的是哪家的数即可。

   **结论或趋势不一样的**，按这个顺序找原因，找到能解释的就停：
   1. **统计范围**：亚马逊类目节点和平台自建类目不是一回事；Top100、全部主商品、父体/子体的样本也不同。抽两家各自的前 20 个商品看标题，看混进来的其他产品占多少销量。
   2. **时间窗口**：自然月还是滚动 30 天、数据截至哪天、当月是否不完整、周数据怎么汇总成月。
   3. **指标定义**：销量还是销售额，Top3 还是 Top10，新品按几个月算，价格是售价、到手价还是加权均价。
   4. **估算模型**：用几个三家都覆盖的 ASIN 比月销，看某家是系统性偏高偏低，还是个别商品估算偏差。
   5. **数据异常**：缺月、某月断崖式突变、返回 -1 或空值、类目树改版。
   6. 以上都解释不了：几家的结论并列写出，标【待核实】，不选边。

   查原因需要补数时，免费的或很便宜的直接写进清单交给 Gemini Flash 拉；要扣费较多的，先把清单和预估费用报给用户。

   **写进报告**：
   - 在受影响的小节正文用一两句话说明：两家结论为什么不同、采信哪家；需要的话把两家放在同一张图里上下对照。
   - 后面各章一律按采信的口径写。给 Argon 的事实摘要里要写明这些差异和采信结论，Argon 不能自己另挑一家的数。
   - 有影响结论的差异没查清时，第 5 步立项最多给“观察”，不能据此下“做”或“不做”。

   **案例（2026-10 首饰盒）**：
   - 价格带：卖家精灵显示销量集中在 $5–15，西柚显示集中在 $34–39。原因是卖家精灵统计的亚马逊节点 Top100 里有 69 个旅行包、戒指盒、礼品袋（占 71.5% 销量），西柚类目只收桌面首饰盒。采信西柚。
   - 大盘同比：Sorftime 节点 1–9 月 -4.8%，西柚 +4.3%。原因同样是节点里混了低价小件，两家不能直接比。

## 三、 按章节分步调研流程

各章节详细报告撰写句式、数据表结构与指标口径对照见 `references/report-template-and-metrics.md`。

### 第 1 步：市场大盘分析（回答“盘子有多大、在涨还是跌、谁在买、头部锁死没有”）

| 小节 | 核心指标与口径注意 | 主数据源（优先调用） | 补充数据源（补齐维度/交叉核验） | 怎么下结论 |
| :--- | :--- | :--- | :--- | :--- |
| **1.1.1 亚马逊大盘** | 近 24 个月销量趋势、相同月份区间同比增减（%）、旺淡季月份与大促表现 | **Sorftime**: `category_report`（Top100 月度销量/销售额汇总，参数 `node_id`, `amz_site`, `query_start/query_date` 跨度 3–40 天，最多回看近 2 年）、`category_trend`（`trend_index=SalesCount`） | **卖家精灵**: `market_research`, `market_product_demand_trend`<br>**西柚**: `get_category_market_size_trends`, `get_category_seasonality` | 对比今年已过月份与去年同月区间总销量算同比；结合 24 个月曲线指出爬坡期、旺季、回落期与 11/12 月大促表现，并输出月度销量数据表。 |

### 第 3 步：VOS 流量分析（回答“站内流量从哪来、投什么词划算、竞品怎么打广告、站外有没有品牌护城河”）

1. **3.1 站内流量入口**：
   - **主数据源**：**西柚（`xydc`）** `generate_category_insight_resource`（获取并复用 `resourceId`）→ `get_category_keywords`（按月获取类目流量词表，每 20 词 1 Credit）+ `get_keyword_info`（一次传 ≤100 词，补齐周搜索量、ABA 排名、建议竞价、点击转化率、Top3 ASIN 点击/转化份额）+ `get_asin_keywords` / `get_parent_asin_keywords`（分析 BSR 头部 ASIN 的关键词流量集中度）。
   - **补充数据源**：**卖家精灵** `traffic_keyword`、`keyword_miner`。
   - **类目词结构分析（BSR Top 5 主力 ASIN 流量集中度判定法，2026-10-29 新增）**：
     - **分析对象**：提取类目 BSR Top 5 中出单最多的 3～5 款代表主力 ASIN。
     - **取词与计算规则（铁律）**：在西柚中提取每个主力 ASIN 流量/订单份额排名前 3 的关键词（Top 3 词窗口）。**必须严格限定为纯实体产品词（如 `cutting board`、`wood cutting board`），坚决剔除场景词（如 `kitchen`、`camping`）、人群词（如 `gifts for dad`）或泛修饰词**。
     - **⚠️ 截断红线（剔除不顺延）**：若 Top 3 中包含场景/泛词（例如第 2 个词是 `kitchen`），**直接剔除该场景词不计，绝不向下自动顺延补充第 4 个词**！即：只基于原生 Top 3 窗口内符合条件的 1～2 个纯产品词份额求和；若 3 个均为产品词则 3 词求和。
     - **三档结构判定标准**：
       1. **流量松散型（长尾主导 / 碎片化）—— 前 3 纯产品词份额合计 < 20%**：类目无绝对统治级大词，订单分散在大量属性长尾词、材质词或多变体中。切忌盲目高价硬打大词，应以“多变体渗透 + 属性长尾词矩阵 + 低出价自动广告”为主。
       2. **混合分布型（大词基本盘 + 稳态长尾）—— 前 3 纯产品词份额合计 介于 30% 左右（20%～40%，核心锚定 25%～35%）**：类目既有大词提供基本盘支撑，又有相当体量的长尾词带来稳定转化，属于最健康的漏斗流量结构。打法采用“1～2 个核心大词打精准防守基本盘 + 材质/功能长尾词规模化放量”。
       3. **大词主导型（超级大词垄断）—— 前 3 纯产品词份额合计 > 40%**：类目流量高度依赖 1～3 个头部大词，呈现“赢家通吃”格局。新品上市必须集中火力、重预算强推核心大词首页自然排位，打进首页前列才能爆发。
   - **官方下拉框深度拓词与云表格（`mj-keyword` Alphabet Soup 字母表拓词法，2026-10-29 新增）**：
     - **拓词执行**：针对类目 1～3 个核心种子词（如 `cutting board`、`wood cutting board`、热点材质词），调用 `mj-keyword`（`~/.gemini/config/skills/mj-keyword/scripts/research.py "<keyword>" [marketplace] --json`）抓取 100% 亚马逊官方实时搜索建议一手数据（涵盖常规建议词、best/cheap/top 高商业意图词、A-Z 26个字母后缀穷举展开词）。
     - **属性提炼（Customer Search Modifiers）**：从官方下拉词中反向提炼买家最关注的核心决策维度：人群受众、材质工艺、尺寸规格、功能结构与常见配件。
     - **独立飞书表格交付**：单独创建一个全新的飞书在线表格（云 Sheet，标题如 `{品类名} 官方下拉框 Alphabet Soup 深度拓词表`），将清洗去重后的完整长尾词库及分类写入表格，并在主报告 3.1 节中挂载或附链接，为新品 Listing 埋词与广告投放提供一手买家词库。
   - **结论输出**：
     - 计算核心大词搜索量份额与点击份额，重点算出 **`点击份额 / 搜索量份额` 比率**及搜索转化率。筛选比率显著 >1 且高转化的精准词作为首发主投词。
     - **输出类目词结构分析结论**：明确给出该类目属于“流量松散型 (<20%) / 混合分布型 (~30%) / 大词主导型 (>40%)”，并定调新品推广策略。
     - 将西柚类目关键词表与 `mj-keyword` 官方下拉框拓词表分别写入独立飞书表格后在文档中引用。
2. **3.2 平均转化**：
   - **商机探测器（POE）段**：若用户未提供后台截图/导出，保留标题并写 `【待补：需后台商机探测器截图/导出（过去 360 天订单量、点击量、平均转化率）】`。
   - **【三方数据】段（必填）**：另起一段，直接采用**主数据源 西柚（`xydc`）** `get_keyword_info` 返回的核心词**点击转化率**、周搜索量及 Top3 ASIN 转化份额（辅以 **Sorftime** `category_report` 的类目平均转化率）给出明确转化水平结论。
3. **3.3 竞品站内流量分析**：
   - **主数据源（走 `agy_pull.sh`（Gemini Flash）批量拉取）**：**西柚（`xydc`）** `get_parent_asin_ad_overview`、`get_asin_traffic`。

   - **补充数据源**：**Sorftime** `tiktok_*` / `reddit_post_search` 核查社媒与评测声量，判断是否存在不可逾越的品牌心智壁垒。

### 第 4 步：VOC 客户之声分析（回答“买家为什么买、为什么给差评、为什么退货、工厂改良重点在哪”）

### 第 5 步：总结与立项决策（含硬门槛快检与 Argon 第二意见）

1. **5 条结构化总结 + 1 条硬门槛与利润快检**：

     - **暂缓/观察（Hold/Watch）**：处于季节性下行期、大盘同比跌幅 >20% 且原因不明，或关键指标的三方差异尚未查清，或关键 POE 退货/专利/利润快检尚未完成（标 `[待核实]` 待补齐后再议）。

## 四、 飞书文档与表格可执行交付规范

1. **五步标准写入流程**：
   - **Step 1 确认目录**：按第 0 步向用户确认的目标飞书知识库（Wiki）节点或云空间文件夹路径准备写入。

### 写入飞书的实操要点（2026-10-29 实测）

- **位置**：用户没指定时放个人知识库（`--parent-position my_library`）。
- **谁执行**：create / overwrite 这类命令固定的写入，交给 `deepseek-offload` 子 agent 让 DeepSeek 原样执行一条命令（DeepSeek 不通改 Gemini Flash）；Claude 先 `--dry-run` 预演，跑完自己回读核对。
- **文件位置**：lark-cli 只读当前目录、`/tmp`、`~/files` 下的 `@文件`；报告和图表 HTML 先复制到 `~/files/<任务名>/`，HTML 块写绝对路径 `<html5-block path="@/Users/.../figN.html"/>`。
- **Markdown 转义（不转义会出错）**：代码格式（反引号）之外，`$` 写成 `\$`（否则 `$34.99～$39.99` 会被当成 LaTeX 公式，金额丢失、附近加粗失效），`<` 写成 `\<`（`<html5-block` 除外），`~` 写成 `\~`；反引号里面一律不转义。不要在正文里写 LaTeX（如 `$\le$`），直接用“≤”。
- **交给 DeepSeek 的命令里，`--content @/Users/...` 路径不要加引号**（路径放在 `~/files` 下本来就没有空格）：2026-10-30 DeepSeek 抄带引号的命令时在末尾多加了一个引号，命令没执行；去掉引号后一次成功。直接用 `opencode-cli run --format json` 跑并从 tool 事件核对实际命令，比再开一个子 agent 省事。agy 在无界面模式下不能运行本机命令，不能作为飞书写入的备用执行方。
- 转换和预演用 `references/md_to_feishu.py`（报告 md → 飞书版 md，复制图表 HTML 到 `~/files/<任务名>/`）。
- **回读核对**：`docs +fetch` 后检查 `<latex` 数量为 0、`$` 数量与原稿一致、`<html5-block` 数量等于图表数、没有残留的 `**`；再在浏览器里打开看一眼。出错时用 `docs +update --command overwrite` 整篇覆盖，保留原链接。
