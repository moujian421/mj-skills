# mj-keyword 🔤 类目词库（广告词库 + 否词库）

产出三张表：
- **广告词库**：值得投放的词，标出词组类别、优先级、**量级（按 ABA 排名分档）**、**各属性维度**、推荐用途和各数据源指标。
- **否词库**：会浪费预算的词，**优先词组否定词根**，每个词根自动列出命中拓词数、命中搜索量和被挡掉的词示例。
- **属性分析**：从全部搜索词归纳出的属性维度（材质、尺寸、功能、场景…），每个值的命中词数、搜索量占比和代表词。

数据来自三处：卖家精灵（拓词主力，月度）、亚马逊搜索框下拉词（补漏，免费）、西柚 + ABA（复核，周度，收费）。

最难也最值钱的一步是**判断搜索意图**。指标只是证据，结论要看"谁在这个词下真正拿到流量和转化"。

> 本 skill 是唯一的词库 skill（原 build-ad-keyword-library 已并入，2026-10-30）。实体在 `~/.claude/skills/mj-keyword`，antigravity / opencode 的副本是指向它的软链接，改这里即可。

下文 `<skill>` 指本 skill 所在目录；`WORK/` 放原始数据，`OUT/` 放中间结果和表格文件，每个任务新建一对，例如 `~/keyword-work/<类目>_<日期>/WORK`。

## 快速模式：只要下拉框拓词

**仅当**用户明确只要下拉框/字母表拓词，或明确说不要词库、不查搜索量时走快速模式。提到广告、投放、词库、否词，或只说"拓词"没限定方式时，先问一句「只要下拉框长尾词，还是做完整词库？」。快速模式只跑：

```bash
python3 <skill>/scripts/amazon_autocomplete.py "<种子词>" <站点小写>          # 可读输出
python3 <skill>/scripts/amazon_autocomplete.py "<种子词>" <站点小写> --json   # 结构化
```

每个种子词请求 30 次（种子词、best/cheap/top 前缀、种子词 + a~z），一般 100～300 词。按「核心建议词 / best·cheap·top 意图词 / 买家修饰维度（人群、功能结构、配件、材质规格）」归纳给用户。下拉词**没有搜索量**，不要编造量级。`failed_requests` 接近 30 说明被拦，几分钟后重跑。到此结束，不走下面的流程。

## 0. 先弄清楚的输入

对话或现有表格里能找到的，就不要再问：

| 输入 | 为什么需要 |
|---|---|
| 站点（US/UK/DE…） | 所有数据工具都要求明确站点，不要默认 |
| 种子词或类目 | 拓词起点。用 Sorftime `category_name_search` 找到的 node 可能不对（AB machine 曾被匹配到 Upper Body Machines），要看节点头部商品确认是目标品类 |
| 自家 SKU 的关键配置（几轮、带不带座椅、电动/手动、尺寸） | **决定哪些词是"配置不适配"**。只给了 ASIN 的话，用卖家精灵 `asin_detail` 或 Sorftime `product_detail` 读标题、五点、属性，自己整理出配置、核心属性词和受保护词根，开始前列给用户看。用户没提供 SKU 时，配置类词按通用词收录（见第 3 节），否词库「适用SKU」填「通用（未提供SKU）」 |
| 核心属性词（如 folding、3 wheel、for home） | 门槛分流时的保留判断，也是"硬性未收录"规则的例外。用户没给时，从自家和头部竞品标题/五点的高频属性词里挑，跑 2.1 前和用户确认 |
| 输出位置（飞书链接 / 新建 sheet 名） | 写入目标。**表格文件名统一为「核心关键词+词库」**，如「cutting board词库」；用现有表格时也改成这个名字（`lark-cli drive +update-title --token "$U" --title "<核心关键词>词库" --as user`），子表名保持 类目广告词库 / 类目否词库 / 类目属性分析 |
| 现成的词库或否词库 | 有的话列名、分级名称、SKU 叫法都要对齐 |

**种子词怎么定**：主种子词 + 2～4 个核心同义词（如 golf push cart、golf cart push、golf walking cart）。不要拿宽泛词（如 golf cart）当种子，结果会被乘坐式车辆带偏。不确定同义词时，用卖家精灵 `traffic_keyword` 反查 1～2 个头部竞品 ASIN 的前 20 个流量词来补（只看词，不必落盘）。

## 1. 读现有表格，对齐口径

用 lark-cli 读用户已有的词库和否词库（命令见 `references/lark-cli.md`），统计这些列的取值：词组类别、优先级、推荐用途、使用说明、否定原因、匹配方式、启用状态。新表沿用同一套词汇和 SKU 代号（如 GC1 / GC2）。

## 2. 拉数据：脚本直连，原始返回落盘

**批量拓词（卖家精灵翻页、下拉框）和西柚复核一律用 `scripts/pull.py` 拉，不要自己调这些 MCP 工具再把结果抄进文件。** 第 0 节查产品配置和同义词、单个词看 ABA 趋势这类少量探查，可以直接调 MCP 工具。 脚本从 `~/.gemini/config/mcp_config.json` 读服务器和凭证，原始返回直接存进 WORK/，只打印统计；数字不经过模型，也不占上下文。不要 cat 原始 JSON，要看什么用 Python 打印统计或少量样本。

第一轮（卖家精灵 + 下拉框，可同时跑）：

```bash
python3 <skill>/scripts/pull.py ss WORK --market US "<种子1>" "<种子2>" ...   # 每页 100，按搜索量降序翻到底
python3 <skill>/scripts/pull.py ac WORK --market us "<种子1>" "<种子2>" ...
```

**卖家精灵 `keyword_miner`** → `ss_*.json`：
- 默认 `minRelevancy 15`，过滤明显不相关的词（AB machine 不加过滤时 2,340 个词，大多是阻力带）。类目很窄时可用 `--min-rel 10`。
- 默认最多 30 页（3,000 词）；打印里出现"未取完"时，先考虑提高 minRelevancy，而不是硬翻。
- 打印的 `月份` 写进表底说明。卖家精灵对当月没数据的词返回上月数据，可能出现两个月份，表底写「主要为 9 月，部分词为 8 月」。

**亚马逊下拉框** → `ac_*.json`：
- 只有词、没有搜索量。作用：卖家精灵里也有的词标「亚马逊下拉框 ✅」（一条保留信号）；卖家精灵漏掉的词（`ac_only`）补进待分类。
- 打印出现 ⚠ 时几分钟后重跑；仍失败就跳过这个来源，报告里说明。

### 2.1 合并 + 门槛分流

```bash
python3 <skill>/scripts/merge_sources.py WORK OUT --attr "<核心属性词,逗号分隔>"
```

它合并各来源、算门槛线、给每个词标分流结果，输出 `OUT/skeleton.json` 和 `OUT/routing.csv`，stdout 给出门槛、各路线词数、`autocomplete` 统计和 `hard_excluded_with_signals`。

门槛怎么来（脚本已实现，报告里要写出数值）：在卖家精灵结果里取有 ABA 排名（`searchRank`）、排名最靠后的 8 个词，**跳过等于"最低档"的搜索量**（常见 140），取月搜索量中位数 ÷ 2。排名和搜索量必须同一家的数据。

分流规则（从上到下，命中即停）。**门槛只决定走哪条路，不删词**；删词只看第一行：

| 情况 | 处理 |
|---|---|
| **月购买量为 1 或为空，且没有 ABA 排名**（只针对卖家精灵的词；`ac_only` 没有卖家精灵数据，不走这张表，直接进分类） | **硬性未收录**（用户定的规则），不查西柚。原因写「月购买量为1或空且无ABA排名」。**例外：含核心属性词的词**照常进入下面几行。带其他保留信号的被排除词列在 `hard_excluded_with_signals`，报告时列给用户决定是否捞回 |
| 高于门槛 | 正常流程：查西柚、看 ABA、分类分级 |
| 低于门槛或为空，但含核心属性词 / 相关度≥60 / 广告竞品≥10 / 有建议竞价 / 在下拉框出现 | 保留，归「B 长尾测试」，使用说明写「搜索量数据缺失，按广告竞争判断」 |
| 低于门槛，以上都不满足 | 不收录，列进报告「未收录」，写出当次门槛 |

- "月购买量 1"和"搜索量 140"一样，多半是估算最低档，说明几乎没有成交。
- 核心属性词见第 0 节，报告里列出用了哪些。不要放 golf、cart 这种宽泛词，否则例外等于废掉硬性规则。（folding golf cart 没有搜索量和 ABA 排名，但有 21 个广告竞品、竞价 $2.70，是真需求词。）
- 下拉框不改变硬性规则，但会进 `hard_excluded_with_signals`。
- 不受门槛限制：竞品型号词、增长快的新词（先保留交给分类）、否词库的词组否定词根（不看词根自身搜索量）、`ac_only`（直接进分类）。

### 2.2 词根表 → 属性字典 + 否词词根 + 规则预分类

几百上千个词不逐条打标签，而是**看词根、写规则、脚本批量套用**（cutting board 实测 1,379 词，一份规则文件分完，残留 33 个人工过目）：

```bash
python3 <skill>/scripts/roots.py OUT/skeleton.json OUT/roots.csv --seed "<种子词里的词，如 cutting board chopping>" --top 170
```

词根表把全部拓词切成单词 / 双词 / with·for 开头的三词片段（单复数归并），给出命中词数、月搜索量合计和代表词，另有 `<数字尺寸 AxB>`、`<英寸数字>`、`<套装数量 set/pack>` 三个伪词根。前 170 行看量大的修饰词，再用 Python 列出低量单词词根（否词候选多在这里）。据此写 `OUT/rules.py`（复制 `references/rules_example_cutting_board.py` 改）：

1. **属性字典 ATTRIBUTES + 主属性顺序 ATTR_PRIORITY**：维度 → 值 → 写法。维度从词根里归纳，不要预设，但要**合并成 6～8 个、每列都有足够覆盖**（cutting board 第一版拆成 11 列，大部分格子是"—"，用户看不出细分；合并后为 材质、尺寸规格、结构工艺、功能卖点、套装组合、使用场景、风格外观、购买意图）。合并规则：
   - 取值只写中文短名，不中英混写；值名里不要用"、"（多值分隔符）。
   - 子类用"父·子"命名（木·枫木、颜色·白、安全·抗菌、跨界·上菜拼盘）：命中子类就不再标父类，属性分析表会自动加一行"父（含细分合计）"，表里筛选"开头是 父"也能汇总。
   - 板体自带的构造（汁槽、带边、把手、端面、折叠）归**结构工艺**；随附的独立物件（刀、支架、托盘）归**套装组合**；无毒、抗菌这类安全诉求单独成"安全·"一组。
   - 产品形态和普通款差异大、却共用类目词的用途（如 charcuterie 拼盘、灶台/水槽盖板）标"跨界·"，和普通场景分开，避免误投大流量跨品类词。
   - ATTR_PRIORITY 按维度搜索量占比和"买家选品时先定什么"排序，材质类通常排第一。
2. **词组否定词根 PHRASE_NEG**：先把每个候选词根命中的**全部**拓词打印出来逐个看，只有命中的词都不相关才用。优先单词词根；会误伤的改成更窄的两词短语（如 rack → board rack / drying rack），仍会误伤的改精准否定。**可能是整板自带功能或套装的词不做词组否定**（cutting board 实测：with holder、with stand、rubber feet、legs、knife set、laser engraved、"look like books" 书本造型款都是真实产品）。
3. **精准否定 EXACT_NEG**、**品牌 BRANDS**、**外语 FOREIGN**、**宽泛词 BROAD**、**核心叫法 CORE**、**拼写变体 TYPOS**。

```bash
python3 <skill>/scripts/classify.py OUT/rules.py OUT/skeleton.json OUT/classified.json
```

它打印各优先级词数、宽泛词清单和"没命中任何属性、也不是品牌/核心/外语"的词，并给每个词标好 kw_type（品牌词/核心词/宽泛词）和 lang（西语/中文/韩语/葡语/拼写错误）。`build_sheets.py` 据此在关键词后面加三列：
- **关键词类型**：品牌词、核心词、宽泛词先判；其余取**主属性**（按 ATTR_PRIORITY 第一个命中的维度，如 large wood cutting board → 材质词），都没命中为"其他长尾"。不用"组合词"，组合词会吞掉大部分长尾，按类型分组建广告时失去意义。
- **属性组合**：命中的全部维度，如"材质+尺寸规格"。
- **语种/拼写**：外语和拼写错误单独标，不占用关键词类型，外语词的材质等属性照常打。

过目这份残留，补品牌、材质和否词，重跑到残留只剩零散长尾为止。在 Claude Code 里，残留超过约 300 个时可以交给 deepseek-offload 粗标（batch-offload skill），Claude 抽查后再写进规则。

规则预分类只是初稿，宽泛/促销意图、品牌词、配置不适配和要查西柚反查的词，要按第 3 节原则复核。然后生成西柚清单（一行一个关键词）：
- `OUT/xy_list.txt`：分流为「正常流程」且没被否定的词 + 准备投放的 `ac_only` 词。
- `OUT/asin_list.txt`：BROAD 里的宽泛词和意图有歧义的词。

### 2.3 西柚复核（收费，先确认再拉）

清单来自 2.2。**先不带 `--yes` 跑一次拿预计 Credits，告诉用户词数和消耗，用户同意后再加 `--yes`。** `--user-task` 填用户发起任务时的原话。

```bash
python3 <skill>/scripts/pull.py xy   WORK --market US --keywords-file OUT/xy_list.txt   --user-task "<用户原话>"   # 约 10 词 1 Credit
python3 <skill>/scripts/pull.py asin WORK --market US --keywords-file OUT/asin_list.txt --user-task "<用户原话>"   # 每词 1 Credit
python3 <skill>/scripts/pull.py asin-summary WORK      # 每词前 10 个 ASIN 一行摘要，用来判断意图
```

- `get_keyword_info` → `xy_*.json`：周搜索量、ABA 排名、点击转化率、竞争难度、建议竞价，以及 `abaReport`（ABA 周期、点击前三 ASIN 的点击/转化份额）。长尾词没有转化率或周搜索量很正常，填 n.a.。
- `get_keyword_asin_analysis` → `asin_*.json`：对每个宽泛词、有歧义的词查一次（page_size 10）。看前 10 个拿流量的 ASIN 是什么产品、价格、自然/广告排名。
- **ABA 怎么读**：Top3 点击份额高、转化份额 0 → 头部点击没转化，意图可能不匹配（表里标红字）；Top1 是自家或直接竞品且点击、转化都高 → 已被头部占住，进入成本高。要看趋势用西柚 `get_keyword_aba_trends` 或卖家精灵 `aba_research_weekly`。
- 西柚拉完后重跑一次 `merge_sources.py`，指标会并进 skeleton。

为什么两家都要看：卖家精灵的均价会误导（golf cart 均价 $8,199 像乘坐式球车词，西柚反查首页几乎都是手推车，应升级投放；ab workout 均价被腹肌轮拉低，首页前 10 有 7 个是腹肌机）。两家竞价没有固定高低关系，周×4.3 也不等于月搜索量，出价参考一定标明来源。

## 3. 分类：判断每个词的搜索意图

类别、判定方法和例子见 `references/classification.md`（广告词库 4 个词组类别 + 否词库否定原因）。2.2 的粗分类在这里用西柚证据定稿。

### 核心原则

- **相关度和平均售价只是线索。** 宽泛词以 keyword→ASIN 的实际流量和转化份额为准。
- **"配置不适配"取决于自家产品。** 同一个词，对三轮车款要否，对四轮车款就是核心词。
- **意图混杂的词不要直接否。** 先放进"C 低预算探索"小额跑，或在否词库标"按搜索词报告启用"。
- **品牌词分两种。** 竞品整机品牌词（如 caddytek push cart）进广告词库做竞品测试，注明不写进自家 listing；竞品配件品牌词进否词库。
- 无法判断意图的词（如不认识的品牌名）列进"未收录"，不要硬塞。
- **"同类"指同品类整机**：腹肌机类目里双轨、弧轨、跪式、坐式都算同类。和自家形态不符的专指词另按"配置不适配"处理。
- **用首页同类占比下结论**（西柚反查前 10 个 ASIN）：
  - 同类 ≥6 个：可以投。转化率不低于核心词一半的进 A2，否则进 C 低预算探索。
  - 同类 4～5 个：意图混杂，进 C 低预算探索。
  - 同类 ≤3 个：进否词库；有一部分同类的用精准否定，标"按搜索词报告启用"。
- **西柚没有转化率时**，依次看 ABA Top3 转化份额、卖家精灵购买率（和核心词比），使用说明里写明用的替代指标。
- **`ac_only` 的词**：按词面和首页反查判断。没有西柚数据时最多进「B 长尾测试」，使用说明写「仅下拉框出现，无搜索量数据」。`best/top` 前缀按普通词判断；`cheap` 前缀一般归「宽泛/促销意图」。
- **没有提供自家 SKU 时**，款式或配置类词先按通用词收录，使用说明写"款式不符时改为精准否定"，报告里说明没做"配置不适配"类否词。

## 4. 分级（广告词库）

| 优先级 | 条件 | 推荐用途 |
|---|---|---|

**量级列**（`build_sheets.py` 自动算，阈值写在 `meta.volume_tiers`，可按类目调）：按 ABA 全站排名（卖家精灵 searchRank，没有再用西柚 ABA 排名）分 ≤1 万 大词、≤5 万 中词、≤20 万 小词、更大为长尾；没有排名的再分「无ABA·有月搜」和「无量·待验」（只在下拉框出现）。用户要的是"ABA 的分类"，所以用全站排名，不用类目内分位。量级和优先级是两列，A1/A2 仍按第 4 节条件定。

## 5. 否词库：词组否定和精准否定

- **词组否定**只用于"词根本身就代表不适配"，如 electric、remote、scooter、kids、disc golf、4 wheel、seat。命中拓词数、命中词月搜索量合计、命中词示例（按量前 8 个）由 `build_sheets.py` 按全部拓词自动算，不用手填。
- **没有自家 SKU 时**，材质、尺寸、款式词都不做否定（不知道哪种不适配），只否类目级不相关的词：配件、耗材、DIY/手工、其他品类。
- **词组否定的词数尽可能少**：有 electric 就不需要 electric golf。前提是更短的词根不误伤要投的词。脚本的 `phrase_root_suggestions` 只是建议，要人工判断语义：品牌名截出来的片段（bag boy → "boy golf"）不要用；通用修饰词（cheap、light、mens、颜色）脚本已排除。
- **受保护词根**：自家卖点和自带配件（umbrella、cooler、phone holder、4-speed、knee pad）永远不做词组否定，写进 classified.json 的 `meta.protected_roots`。
- **外语泛词不能单独做词组否定**：西语 maquina de ejercicios para abdomen 就是"腹肌训练机"，单独否 ejercicios 会一起挡掉。改成"泛词 + 不适配场景"的短语（ejercicios en casa），或逐条精准否定。英文泛词（workout、exercise、fitness）同理，先看影响面清单。
- **一个词根只要会挡住一个相关词，就不能做词组否定**，改更长的短语或精准否定。踩过的坑：for sale 误伤 golf push carts for sale；cooler、umbrella 误伤带配件的整车词；golf cart、golf bag 这类宽泛词根同理。
- **不要重复否定**：被词组否定覆盖的精准否定、比另一个词组否定更长的词组否定都删掉（脚本 `redundant_negatives`）。
- 复数不一定被覆盖（scooter 不一定挡住 scooters），量大的复数另加精准否定。
- 配件词和整机意图混在一起（golf push cart phone holder），启用状态写"按搜索词报告启用"。
- 排序：词组否定在前；精准否定按启用状态、原因、搜索量排序。

## 6. 生成表格、检查、写进飞书

在 skeleton.json 上补 category、priority、use、note；否定的词从 ad 移到 neg，不收的加进 excluded；另存为 `OUT/classified.json`（字段见 `scripts/build_sheets.py` 开头），然后：

```bash
python3 <skill>/scripts/build_sheets.py OUT/classified.json OUT
```

脚本生成 ad.csv、neg.csv、attr.csv（有 `meta.attributes` 时）、表底说明 CSV、styles.json 和分批的 styles_NN.json，并检查：`phrase_conflicts`（词组否定误伤广告词，有就改精准否定）、`duplicates`、`plural_hints`、`redundant_negatives`、`phrase_root_suggestions`、`watch_conflicts`（误伤带保留信号的被排除词，逐条判断）、`protected_violations`、`unclassified`（所有拓词必须进广告词库、否词库或 excluded 之一；被词组否定挡住的自动算已分类）。

**逐个过目词组否定的影响面**：`phrase_coverage.csv` 列出每个词组否定挡掉的每个词。写入前至少看完命中数最多的前 10 个词根和所有带 ⚠ 的行；挡掉相关词就按第 5 节改，重跑脚本，直到 ⚠ 行都确认过。**有警告先处理，处理完再写入。**

**ABA Top1 ASIN 标注**：反查时看到过标题的 ASIN，把品牌或产品类型写进 `WORK/aba_names.json`（`{"ASIN":"品牌"}`），重跑 merge 自动加注。不要为了加注专门调付费接口，除非这个词是 A1/A2 且 Top1 是谁会影响判断。

某组数据缺失（如没有西柚权限），对应字段填 null，表里显示灰色 n.a.，报告里说明。

写入飞书按 `references/lark-cli.md` 的顺序：建 sheet（广告词库、否词库、属性分析三张）→ csv-put → 写表底说明 → 逐个 styles_NN.json 提交 styles-put → 建筛选。**这些命令是固定的：写成一个 shell 脚本一次跑完**，每条输出重定向到 `OUT/lark.log`，只打印每步成败；失败时只看 log 里那一条。两个坑：lark-cli 只读当前目录下的文件，脚本里先 `cd` 到 CSV 所在目录再用相对路径；styles-put 每次最多 1000 条。用户要求清空原表时，先整本导出 xlsx 备份，再建新表、删旧表（见 lark-cli.md）。

排版（用户明确要求过）：
- 写入前先读原表布局；**写数据和排版同一次交付完成**。
- 数值列存成数字再设格式（千分位、百分比、$0.00）。
- 四组数据用不同颜色表头（卖家精灵蓝、下拉框紫、西柚绿、ABA 橙），写清口径（月 / 周、ABA 周期）。
- 优先级、启用状态用浅色底；"n.a."和"—"灰字。
- 冻结首行首列，加筛选；表底合并一行写数据来源、抓取日期、分级口径和注意事项。
- 新 sheet 放在用户原有同类 sheet 旁边，指定了位置以指定为准。
- 清空、删除类命令只对自己新建的表或用户明确同意覆盖的区域执行。
