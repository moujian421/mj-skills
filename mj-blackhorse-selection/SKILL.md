# 黑马选品（mj-blackhorse-selection）

2026-11-03 建立，在 Upper Body Machines（23533924011）、Bait Storage（3408971）上试跑并修正；同日重构结构（筛选门槛不变），把两次试跑都漏掉的 keepa、CPC、专利检查写进固定拉数清单。

**目标**：找出“功能已被市场验证 + 有价格或形态平替空间”的品。逻辑是：低评产品能自然冲进头部，说明需求缺口大、现有竞品防线弱；我们用供应链降本、形态微调或同等功能平替，在核心效用不变的前提下做出价格优势。低评冲榜也可能是大额促销、老链接翻新、Vine 堆分、变体挂靠或季节性造成的假象，所以先排雷再下结论。

## 固定规则（用户定的，改 skill 时不要动）
- 满月门槛：月销 ≥ M × 1.5，且绝对值 ≥ 50 件。
- 促销排雷只看 BD：增长期内有折扣超过 25% 的 BD，且时间重合，才排雷。普通优惠券、小幅降价不排雷。
- 不判断“广告硬推”：只靠第三方插件的数据判断不准，所以不查广告流量占比，也不因为广告多而剔除。
- 广告成本固定按售价的 15% 计，不按 CPC 估算。

## 数据纪律
- 每个模块末尾写一行“数据来源：接口名（统计周期）”，不必逐个数字标注。
- 区分【实测】（接口原始返回）和【推算】（汇率、头程单价、1688 匹配度等），推算写明依据。
- 接口没数据写 `N/A`，不估算补齐。
- 候选品不够时如实说，不悄悄放宽阈值；要放宽，先列出放宽哪一条、放宽后多出哪些品。
- 不用浏览器插件，数据全部从接口取。

## 流程

每一步的拉数都写成清单交给 batch-offload：先用 `oc_pull.sh`（DeepSeek）；DeepSeek 额度用完（429 free-limit）改 `cb_pull.sh`（CodeBuddy hy3，每批 5 行）。只有 1–2 次的小查询 Claude 自己调。原始返回不读进上下文，只用 Python 打印汇总。

### 第 0 步：确认输入（全流程只停这一次）
1. 卖家精灵 `product_node`（keyword 填节点 ID）查 nodeIdPath 和类目名。
2. 西柚 `search_market_insight_categories` 用类目名搜对应类目（免费）。
3. 一次性向用户确认：
   - 类目名和节点是否对；
   - 西柚对应类目（要扣 Credits；搜不到就说明跳过）；
   - 第四步的外观专利查询（Sorftime `patent_search_from_image` 每次扣 450）：查不查、查几个；
   - 售价区间（没给就用默认 < $100）和排除品类。
   - 候选不够时的处理：默认不放宽，报告里列出“若放宽哪一条会多出哪些品”，由用户事后决定。
4. 确认后一路跑完，不再中途停。

### 第 1 步：类目基准 + 初筛池（第 1 轮清单）
- 卖家精灵 `market_research_statistics`：Top 100 平均月销 **M**、价格、上架时间、评论数分布。阈值统一用卖家精灵的 M（其他来源的 M 只作参考）。
- Sorftime `category_report`：类目体检（见“辅助参考”）。
- 卖家精灵 `product_research` 两次：按售价区间，size 100，按 total_units 降序；一次加 maxRatings 100，一次不加（后者用来找同节点老链接和锚定价）。
- 用户确认西柚类目后：西柚 `discover_breakout_products`、`get_category_surging_ranking`、`get_category_new_release_ranking` 交叉补充初筛池。

**初筛池**：售价区间内、Review < 100、上架 ≤ 180 天。`product_research` 要翻完所有页（size 100，看 pages 字段）：未满月新品累计销量低，常排在 100 名以后，只看第 1 页会漏掉（2026-11-03 Stained Glass Tools 试跑踩过）。

### 第 2 步：销量门槛与低评硬指标（Python 筛）
按上架天数分两条路：

**已满月（上架 ≥ 30 天）**
- 子体近 30 天销量 ≥ M × 1.5，且 ≥ 50 件。`product_research` 的 units 是父体口径，所以：先用父体 units 粗筛，过线的再在第 3 步用 Sorftime 日销近 30 天合计确认子体销量；父体由多个变体撑起时，标出主力子体。
- 近 3 个月月销持平或上升（卖家精灵 `asin_sales_trend` 或 `keepa_info`）。

**未满月（上架 < 30 天，且有 ≥ 14 天日销）**
数据源：Sorftime `product_trend`（DailySalesVolume），用 `keepa_info` 或西柚 `get_asin_bsr_trends` 的 BSR 交叉核对。
- 阶梯增长：起点 = 7 天前的 3 日均值，终点 = 最近 3 日均值。

  | 起点日销 | 终点日销要求 | 增长率 |
  |---|---|---|
  | 2 | ≥ 5 | ≥ 150% |
  | 5 | ≥ 10 | ≥ 100% |
  | 10 | ≥ 16 | ≥ 60% |

  两档之间线性插值；起点 < 2 按“终点 ≥ 5”；起点 > 10 按“增长率 ≥ 60%”。
- 平滑度（近 14 天）：单日峰值 ÷ 14 天均值 ≤ 2.5；最近 3 日均值 ≥ 峰值的 70%。

**低评硬指标（两条路都要满足）**：Review < 100（优先 < 50，按父体计），且节点小类 BSR ≤ 50。

第 2 步只用第 1 轮数据粗筛（父体 units、上架天数、Review 数、小类 BSR）。子体日销、近 3 个月趋势、阶梯和平滑度在第 3 步拉到数据后再判，不过线的在第 3 步剔除。

**进入第 3 步的顺序**：
- 未满月新品：粗筛通过的全部进第 3 步（它们累计销量天然低，不和满月品一起排）。
- 已满月：按父体月销降序，先取前 5。
- 第 3 步有品被剔除时，按顺序从后面递补，直到存活 5 个或池子用完；不足就如实写。

### 第 3 步：候选深查 + 排雷（第 2 轮清单，每个候选品一组）
| 接口 | 用途 |
|---|---|
| Sorftime `product_trend` DailySalesVolume | 子体日销、近 30 天合计、阶梯和平滑度 |
| Sorftime `product_trend` ReviewCount | 评论突增/骤降 |
| 卖家精灵 `keepa_info` | 真实上架时间、断货重启、价格历史（老链接核查） |
| 西柚 `get_asin_info_trends`（近 3 个月） | 价格、BD、优惠券时间线 |
| 卖家精灵 `review` starList [1,2,3] | 差评痛点 |
| 卖家精灵 `review` typeList [4] | Vine 评论数 |
| Sorftime `ali1688_product_search_from_image`（主图改 `._AC_SL500_.jpg`） | 1688 同款与采购价 |
| 卖家精灵 `asin_detail` | 包装尺寸、重量、FBA 费、品牌、卖家全名 |

另加：
- 每个核心词一次卖家精灵 `keyword_research_trends`（季节性，没数据时用 `google_trend`）和一次 `keyword_research`（搜索量、CPC，写进推广阻力备忘）。
- 每个候选品的品牌一次 `competitor_lookup`（按 brand，查同品牌老链接）。品牌名第 1 轮 `product_research` 里就有，可以和上面一起放进同一轮清单。
- 备用：1688 以图搜图匹配不上时用 Sorftime `ali1688_product_search`（文字）；卖家精灵 `review` 没返回时用 Sorftime `product_reviews`。

**排雷（命中任一项剔除，或降为“观望”并写原因）**
- **促销驱动**：增长期内有折扣 > 25% 的 BD，且与增长时间重合。折扣率按促销前的日常成交价算。
- **老链接翻新**：同品牌（`competitor_lookup` 按 brand）或同节点（第 1 步不限评论的那份 `product_research`）里有同款老链接，尤其是低星老链接，新链接只是降价重上；或 `keepa_info` 显示上架时间早于宣称、断货后重启、评论数突增或骤降、评论数和销量明显不匹配。
- **Vine 堆分**：Vine 占全部评论 ≥ 50% 时，星级不能当买家验证。
- **季节性**：核心词正处于季节高峰，非全年需求。
- 不做“广告硬推”排雷（见固定规则）。

### 第 4 步：店铺反查（第 3 轮清单）
- 对通过排雷的品，用卖家精灵 `competitor_lookup`（sellerName 写 `asin_detail` 里的卖家全名）或 Sorftime `seller_search` 拉店铺全部商品。
- 挑上架 ≤ 180 天、同样低评、销量递增的商品，按第 2、3 步同样标准（含排雷）再筛一遍（补一轮第 3 步清单），通过的并入候选池。主池存活品和店铺补充的存活品合并后，按同样顺序重排，取 Top 5 进第 5 步。
- 同一轮清单里，给差评少（1–3 星 < 10 条）的候选品补拉同细分低星竞品的 1–2 星 `review`。
- 店铺画像：上新节奏、价格带、是否同一供应链或品类路线；成熟大卖（靠品牌带量）还是新店。

### 第 5 步：痛点、平替与利润（只对候选池 Top 5）
**1. 差评痛点**（Python 汇总时打印：日销周均值和近 14 天、价格变化点、差评、1688 前几条、店铺 Top 商品）：1–3 星评论归纳前 3 个高频问题和占比。目标品差评太少时用同细分低星竞品的 1–2 星补充，注明来源。评论 ≥ 30 条时按 batch-offload 交 DeepSeek 打标签，Claude 抽查。

**2. 功能平替**
- 1688 以图搜图，记录阶梯采购价和同款匹配度；匹配错就写 N/A。
- 想清楚能否用更成熟、更便宜的工艺做出同样功能（车削改注塑、一体改分体、减零件等）。
- **差评集中在“材质薄、易坏、不耐用、进水”时，禁止减料降本**，也不能砍掉买家买单的核心结构，只能从结构、工艺、供应链整合上降本。

**3. 包装与物流**：用 `asin_detail` 的包装尺寸和重量，测算压缩包装后能否降一个 FBA 尺寸分段，以及头程能省多少。

**4. 利润测算**：目标售价 = 竞品现价下浮 15% 和 25% 两档。
- 成本：采购（1688 人民币价 ÷ 汇率）+ 头程 + 佣金 + FBA 配送费 + 月仓储费 + 退货损耗 + 广告（售价 × 15%）。
- 退货损耗 = 退货率 ×（采购 + 头程 + FBA）。带电产品按带电专线头程、退货率 8% 再算一遍压力测试。
- **广告前净利率 ≥ 30%**（扣除广告以外全部成本）；**广告后净利率 ≥ 15%**。
- 不达标写明差多少、哪一项成本超了。
- **价格锚定**：降价后的售价和同细分同款白牌、老款的主流最低价比；仍高于锚定价就视为没有价格优势，按锚定价再算一次。

### 第 6 步：立项关卡（一票否决）
- **专利**：按第 0 步用户确认的范围查美国外观专利，高相似且有效的直接淘汰；发明专利风险写进备忘。没查的写“未查”。
- **推广阻力**：第 3 步 `keyword_research` 的搜索量趋势和 CPC，只写进备忘，不作剔除依据，也不改广告成本假设。
- **合规**：列出可能需要的认证（CPC、FCC、FDA、UL、加州 65、锂电池 UN38.3 / MSDS / 危险品），标【推算】，不确定写“待确认”。
- 专利、合规没查完时，“重点推进”必须写前置条件（如“专利和危险品审核通过前不下单”）。

### 第 7 步：写报告 + Argon 复核
- 报告放会话文件夹，文件名 `试跑报告_<类目>.md`，格式按下面的“输出格式”。
- 把本 skill 和报告一起交 agy 的 `gemini-4-argon-medium` 挑刺（规则违规、数字矛盾、被忽略的反面证据、推算假设）。Claude 逐条核对，需要补数就补查，然后改报告，并向用户说明采纳了哪些、哪里有分歧。

### 辅助参考：Sorftime 类目体检（不作剔除门槛）
`category_report` 的 Top 100 CR3 / CR5、亚马逊自营占比、主流价格带、平均毛利区间、新品占比、退货率。给风险标签：高垄断成熟期 / 弱品牌成长盘 / 极端红海低价盘。类目垄断但细分没有大牌时单独说明。

|---|---|---|---|---|---|---|---|---|---|---|---|

被剔除的品单独一张简表：ASIN、剔除原因、触发的数据。

### 2. 单品档案（每个“重点推进”和“观望跟进”的品一份）
**2.1 目标品与店铺**：形态、规格、定价；销量验证（对比 M，或阶梯起点 → 终点、增长率、平滑度）；Review 数、星级、上架天数、Vine 占比；排雷各项结果；店铺反查发现；同细分主要竞品的售价、月销、评论、星级；类目体检标签。

**2.2 为什么卖得动**：满足什么刚需或细分场景；为什么评论极少时买家也愿意下单（功能独占、视觉差异、价格、文案切中痛点），用主图、标题、五点、关键词流量作证据；列出不支持立项的反面证据。

**2.3 “功能等效 + 价格更优”方案**：材质/结构平替及节省；包装与物流重构（压缩后尺寸、能否降 FBA 分段、头程节省）；针对第 1 痛点的 1 个低成本改进及预估增加成本。

**2.4 商业可行性**：目标售价 vs 竞品售价 vs 锚定价；成本拆解表（每项注明【实测】或【推算】）；两档 + 锚定价情景的广告前/后净利率；专利、合规结果和推广阻力备忘；**立项建议**（重点推进 / 观望跟进 / 放弃）+ 核心原因 + 还缺哪些数据。

### 3. 未执行或偏离的地方
没调用的接口和原因、改用的数据源、没做的检查。

## 踩过的坑
- `product_research` 的 `units` 是**父体口径**（同父体子体数字一样），子体月销用 Sorftime 日销近 30 天合计。
- hy3 遇到超过约 50KB 的返回会另存文件，raw 里只留路径；用 `grep -o '/Users/cathug/.codebuddy[^ ]*\.txt'` 取路径再读。
- 店铺反查 `sellerName` 要写完整名（“Arcpro Outdoor” 查不到，完整名是 “Arcpro Outdoors”），从 `asin_detail` 取，不用表格里截短的名字。
- 西柚 `get_asin_order_trends` 只有月度数据；`get_asin_info_change_trends` 只看标题和主图。日销用 Sorftime，价格和促销用 `get_asin_info_trends`。
- 西柚类目接口扣 Credits，必须先确认；用类目名或 ASIN 都搜不到就跳过并写进报告（两次试跑都没搜到）。
- Sorftime `patent_search_from_image` 每次扣 450，只在第 0 步确认过的范围内查。
- `product_research` 的上架天数可能不准（Zinc Came 写 84 天，实际约 50 天）；上架时间以 `asin_detail`、keepa 最早排名记录、Sorftime 日销起始日交叉判断。
- 两次试跑都漏了 keepa 老链接核查和 CPC：现在已写进第 3 步固定清单，不要再省。
